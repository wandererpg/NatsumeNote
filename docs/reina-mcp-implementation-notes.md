## 实现决策

- 官方 SDK + InMemoryTransport 的 MCP 生命周期留在主进程，SQLite 工作放在 utilityProcess。最大 8 个并发等待，3 秒超时会终止查询进程并拒绝在途请求，下一次查询重新建立进程。
- 来源路径由原生文件选择器授权，只以 UUID 暴露给界面。文件身份与绑定的资料 ID 每次复核。候选预览有时效与容量限制，确认时重新读取名称和编号，忽略渲染层传来的显示名。
- 来源替换后重新选择相同路径保留旧关联，标记待确认；不自动让旧 ID 读取新库。仅在用户确认候选后恢复。断开明确清理本地关联，历史手账不变。
- 同名不同 provider 标签独立筛选，索引只存最小标签投影。会话不建立永久镜像；手账只保存用户明确选择的历史快照。
- 原设计允许跳过无效会话并报告数量。实施采用整次拒绝，避免部分合计伪装完整；这项差异已写入使用说明。分开保存来源累计和会话合计，缺失/不一致有提示。
- 最后断开停止查询子进程；轻量的共享 MCP transport 保留到服务退出。在途逻辑在异步返回后检查服务状态，避免退出后使用已关闭本地数据库。

## 验收范围

- 单元与组件测试覆盖只读/未知结构、单位、空值、WAL、分页快照、范围、参数/错误分类、原生选择授权、预览确认、防重绑、来源替换/重启、标签 AND、手账持久化/导出与陈旧响应。
- 数据库升级测试从合成 schema 8 布局升级到 9，逐行比较原音乐/手账内容，验证外键清理不会删除旧内容。
- `scripts/smoke-reina.mjs` 使用真实 Electron、原生 better-sqlite3、官方 MCP 和独立查询进程，验证来源文件哈希保持一致、分页、统计、标签，以及主循环响应和超时恢复。
- `scripts/smoke-reina-ui.mjs` 使用实际组件/CSS和合成桥接，在 960×640 下检查已连接、未连接、加载和失败状态，无横向溢出，并截图复核长名称、长标签与统计区。不是完整安装版端到端测试。
