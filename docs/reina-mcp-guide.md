# ReinaManager 游玩记录连接

此功能已接入 NatsumeNote 开发源码，现有 0.1.0 EXE 未更新。所有连接与操作都在 NatsumeNote 内完成，不需要修改 ReinaManager。

## 使用流程

### 批量导入全部游戏

确认导入或手动关联后，已打开的作品概览会自动重读关联和资料。加载网络资料时，优先使用已确认 ReinaManager 关联中的唯一 VNDB/Bangumi 编号，不再按新文件夹名重复搜索；旧版本留下的“待选择”“未匹配”或无编号的失败缓存也会自动尝试恢复。已有匹配的本地资料（包括手动确认的选择）优先保留。来源没有编号、编号冲突或关联待重新确认时，仍需核对候选。

网络资料需要联网；请求失败会显示加载提示，刷新期间保留已有简介。可打开“编辑作品资料”刷新重试。网络失败会保留已知编号并限制自动重试频率，手动刷新可立即重试；作品、手账和 ReinaManager 游玩记录不依赖网络资料加载成功。

连接数据库后，在该来源下点击 **预览并导入全部作品**：

1. 程序分页读取全部来源游戏，包括尚无游玩时长的作品。已有明确关联优先沿用，其余按唯一 VNDB/Bangumi 编号或完整标题自动匹配。
2. 没有匹配的默认 **新建作品及文件夹**，位置为当前设置中的音乐库目录。预览会展示根目录和新作品名称；Windows 不支持的字符会替换，重名目录会加序号，已有文件夹不会被覆盖。
3. 用每行下拉框手动选择 **关联已有作品**、**新建作品及文件夹** 或 **跳过此作品**。同名歧义、不同资料编号、多个来源指向同一作品时必须手动处理；已有来源关联只能保留或跳过，重新绑定前需先解除旧关联。
4. 核对新建、关联、跳过及待确认数量，点击 **确认导入**。存在待确认或重复匹配时，会提示原因并定位对应下拉框（包括其他分页），不会保存未处理的批次；也可点击 **处理待确认作品** 逐项跳转。全部跳过时会提示先选择作品。导入成功后作品列表自动刷新，在作品概览的游玩记录中查看来源历史总时长、会话与时段。

重复导入沿用已有来源关联，不重复创建作品。预览有效期为 5 分钟，期间来源游戏或本地音乐库变化时需重新预览。整个批次统一提交；失败时撤回本次数据库写入，并清理本次创建且仍为空的作品目录。

新建的是 NatsumeNote 的作品和空文件夹，不复制游戏程序或音频；原有音乐、手账和来源数据库保持原样。游玩数据通过只读来源关联读取，不伪造缺少时间信息的历史会话。若只需处理一部作品，也可继续使用下面的单作品关联流程。

### 单作品关联

1. 启动 NatsumeNote 开发版，打开设置中的 **ReinaManager → 数据连接**。
2. 点击 **选择 ReinaManager 数据库…**，通过系统文件选择器选中实际使用的 `reina_manager.db`。安装版与便携版的位置可能不同，程序不会猜测或自动授权路径。可点击 **测试读取** 检查连接。
3. 打开本地作品，切换到与“作品资料”同级的 **游玩记录** 页签，在页面下方选择来源，点击 **浏览全部来源作品**。也可以通过作品名称、VNDB ID 或 Bangumi ID 搜索。两边译名或文件夹名不同导致搜索无结果时，直接浏览全部作品即可，候选列表支持分页。
4. 查看候选作品的名称、资料编号与标签，选中后先预览 **来源总计**。核对后点击 **关联此作品**，即读取原有历史时长和游玩时段，无需重新计时。名称相同不会自动关联；已有本地作品资料的编号匹配只提供推荐。每个来源作品只能关联到一个本地作品。
5. 页面上方显示 **来源总计** 与 **每日游玩时长** 折线图，下方保留数据来源和作品关联设置。同一天的记录合并显示，悬停图表或聚焦后使用左右方向键可查看日期与时长。历史分页会自动读完后统一显示；需要更新时点击 **刷新**。页面不再提供日期范围筛选、会话累计或会话列表；首次关联与刷新仍会更新本地的最小标签缓存。
6. 在该作品的手账中打开 **游玩记录** 侧栏，选择最多 20 条记录，确认插入。卡片支持保存、重新打开、复制、撤销/重做、记忆模式和 SVG 导出。

取消文件选择不会产生连接。解绑作品或断开来源只清理 NatsumeNote 的关联及对应标签缓存，保留音乐、手账卡片和 ReinaManager 数据。重启后已确认的关联仍然存在。来源文件被替换后，可通过系统选择器重新选择原路径：保留 sourceId 与旧关联，但清除外部标签缓存并暂停旧关联读取。作品概览会提示先解除旧关联、再搜索确认，避免把旧作品编号自动套用到新库。路径改变时作为新的来源连接，不会自动搬迁旧关联。

## 数据库在哪里（Windows）

设置中的“数据连接”会直接显示以下位置与查找步骤：

| ReinaManager 版本 | 数据库位置 |
| --- | --- |
| 安装版 | `%APPDATA%\com.reinamanager.dev\data\reina_manager.db` |
| 便携版 | `<ReinaManager.exe 所在目录>\resources\data\reina_manager.db` |
| 开发版 | `%APPDATA%\com.reinamanager.dev.debug\data\reina_manager.db` |

安装版可按 **Win + R**，输入 `%APPDATA%\com.reinamanager.dev\data` 后回车；也可以把该文件夹路径粘贴到选择数据库窗口的地址栏，再选中 `reina_manager.db`。`%APPDATA%` 会指向当前 Windows 用户的 `AppData\Roaming` 文件夹。

便携版可右键 ReinaManager 快捷方式，选择“打开文件所在的位置”，再进入 `resources\data`。若文件不存在，先确认已启动并使用过对应版本。以上规则已核对 ReinaManager 的 `reina-path/src/paths.rs` 与 `runtime.rs`，不同旧版本仍应以实际使用的文件为准。

## 如何理解时长

**连接成功但没有时长？** 连接数据库与关联作品是两步。仅选择数据库不会自动将来源游戏对应到本地作品；需要在各作品的概览中浏览、选中并确认关联。未关联时界面会明确提示，不会以 0 分钟冒充已有统计。预览只读取所选作品统计，不保存关联；取消选择不会改变本地记录。预览失败可重试，来源未提供累计值时显示“来源未提供”。

- **来源总计**：ReinaManager 保存的生命周期累计分钟，可能经过历史修正。缺失值显示为来源未提供。
- **每日游玩时长**：按本机时区的会话开始日期汇总来源保存的分钟。同一天多次游玩会合并，两次游玩日期之间的空白日显示为 0；跨午夜记录完整归入开始日期。
- 折线图读取全部已保存会话，数值不覆盖来源总计。来源时长已四舍五入为分钟，不能用结束时间减开始时间代替，也不代表秒级精度。
- 只能看到已落库的会话，无法据此判断游戏是否正在运行，不提供实时计时。游玩时长独立于音乐播放时长。

手账卡片保存插入时的历史快照：刷新来源、改关联或断开连接不会改写已有卡片。卡片合计仅计算选中的会话；来源累计作为独立参考值保留。

## 标签

作品概览汇总所有已匹配的 VNDB/Bangumi 资料以及已关联、已读取的外部标签；相同名称的不同来源标签独立展示、独立选择。默认显示 12 个，可展开全部。多选为 AND，即作品必须同时具备所有选中的来源与标签组合。

筛选覆盖整个本地作品库的已缓存资料，不限于屏幕中已显示的卡片。来源尚未关联或尚未读取的外部标签不会参与筛选。刷新使已选标签失效时会清理条件并提示。手账页面自身的整理标签独立保留。

## 首版范围与兼容性

- 使用官方 `@modelcontextprotocol/sdk@1.32.1`，通过 `InMemoryTransport` 完成初始化、列举工具与调用；SQLite 查询在 Electron 独立 utilityProcess 内执行，超时会终止进程，下一次查询可重新建立进程。
- 五个只读工具：`reina_get_connection`、`reina_list_games`、`reina_list_sessions`、`reina_get_stats`、`reina_get_tags`。成功返回结构化信封及快照、读取时间、提示；连接诊断的 snapshotId 为 null。业务错误通过 `isError: true` 返回安全的 `code/message/retryable`，在进程间和 MCP client 保留分类。IPC 按已有应用错误类型映射为可展示消息，不扩展旧消费者的错误枚举。参数校验失败仍由协议报告。
- 当前是 NatsumeNote 托管的本地兼容桥，不是 ReinaManager 原生 MCP。未开放网络端口、外部 stdio 服务或任意 SQL 工具，也不支持 AI 修改关联或自动写手账。
- 按参考仓库提交 `89c0c07d2971575109fbb565ef091b59329ca59e` 核对基础结构与单位，并在 `4d2c9440bdbd088a73e1c4abf95a7b9ae35dc31c` 增量核对第 22 次迁移；要求具有已核对的 SeaORM 迁移记录和所需表/列。现支持截至 `m20261006_000022_nextmoe_oauth` 的已核对迁移。无迁移历史、未知迁移或关键列不兼容时仍拒绝读取。不能保证任意已安装版本都兼容。
- 来源以 `readonly + fileMustExist + query_only` 打开；不对来源执行迁移、检查点或清理。文件路径仅保存在本地主进程数据库，不返回渲染层或写入手账卡片。
- 每次快照最多 50,000 条记录或 16 MiB，最多保留 4 个、总计 64 MiB、5 分钟有效；游标绑定来源、作品、范围及工具，过期需刷新。来源目录最多 5,000 个作品、40,000 条资料来源行，每个作品最多 300 个标签。超限会报错，不会静默显示部分会话合计。
- `get_stats` 可在同一快照覆盖的更小范围内重新计算；超出覆盖范围或请求不存在的作品时返回 INVALID_INPUT。遇到无法解释的会话行，整次读取失败，不提供看似完整的部分累计。相较原方案的“跳过并计数”，首版采用此保守策略；必须修复或核对来源记录后重试。
- 游玩统计成功后，附带标签刷新失败只产生提示并保留旧标签。最后一个来源断开时停止查询子进程；共享的进程内 MCP transport 随 NatsumeNote 服务退出关闭。
- 本地迁移从 schema 8 升至 9，只增加来源、关联和最小标签索引。没有复制 ReinaManager 的组件或翻译词典。

若读取失败，先核对所选文件是否属于实际使用的 ReinaManager。来源正在保存时可稍后重试；持续占用时可关闭 ReinaManager 后重试。不要用 NatsumeNote 自身数据库作为来源。

含第 22 次 `nextmoe_oauth` 迁移的来源曾被旧开发版误拒绝，现已核对并支持，详见 [兼容修复记录](reina-mcp-compatibility-22.md)。更新后需退出并重新启动 NatsumeNote，再选择原数据库；无需修改来源或删除游玩记录。

## 开发与验证

```powershell
Set-Location 'D:\Codex\NatsumeNote'
npm run dev
```

完整检查遵循 `AGENT.md`。另外可运行以下合成数据检查，不访问真实用户数据库：

```powershell
npm run build
node scripts/smoke-reina.mjs
node scripts/smoke-reina-ui.mjs
```

前者验证真实 Electron 进程、官方 MCP、原生 SQLite、分页、时长单位、源文件内容不变和超时恢复；后者检查 960×640 下的连接、空状态、加载、失败、浏览作品与历史时长预览，以及批量导入预览、加载和失败共 8 种布局状态，截图位于未纳入 Git 的 `artifacts/reina-ui/`。
