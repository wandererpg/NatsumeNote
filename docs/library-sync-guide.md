# NatsumeMusic 与 NatsumeNote 手动双向同步

本功能已加入两端开发源码。现有已安装 EXE 没有被替换；两端都需要启动本次更新后的开发版，后续明确要求打包时再生成安装包。

## 启动开发版

分别在 PowerShell 中运行：

```powershell
Set-Location "D:\Codex\galgame music app\galgame-music-app"
npm run dev
```

```powershell
Set-Location "D:\Codex\NatsumeNote"
npm run dev
```

已有数据库会在应用启动时执行兼容迁移；不要把两端指向同一个正在使用的数据库文件。

## 从音乐软件同步到 NatsumeNote

1. 在音乐软件中打开「设置」，找到「两端数据同步」，点击「导出同步文件夹」，选择存放位置。
2. 导出完成后，保留完整的 `NatsumeSync-…` 文件夹，其中包括 `manifest.json` 和 `assets`。复制到其他位置时也要整个复制。
3. 在 NatsumeNote 中进入「设置 → 两端数据同步」，点击「选择同步包并预览」，选中刚导出的 `manifest.json`。
4. 查看作品、歌曲、播放列表数量和差异；预览阶段不会写入音乐库。
5. 选择冲突处理方式，然后点击「确认合并」。默认「保留本地内容」；希望接收另一端的收藏或歌曲信息变化时选择「采用同步包内容」。
6. 等待「合并完成」。此时新增文件已经复制到目标音乐库，可以移走同步文件夹；它不参与后续播放。

## 从 NatsumeNote 同步回音乐软件

交换上述来源和目标，再导出一个新的同步文件夹，预览并确认合并。此方式按需手动执行，不会自动监控另一端，也不会自动传播修改。已有歌曲按作品和文件内容识别，重复导入同一同步包不会重复收录。

## 合并规则

- 包含受音乐库管理的歌曲文件、歌曲名称/排序/分类/时长、收藏、播放列表、作品封面及 VNDB/Bangumi 资料。
- 冲突处理作用于已有记录：采用同步包内容会更新对应歌曲信息、收藏、封面、作品资料和播放列表名称。
- 作品通过原 ID、已关联资料或规范化名称识别；已有作品名称与目标端 ID 保留，避免破坏手账引用。
- 播放列表合并双方成员。另一端删除的歌曲、作品、收藏列表成员不会作为删除指令传播；已有收藏状态可按冲突策略更新。
- 手账页面、手账素材、设置和背景不参与同步。NatsumeNote 原有手账继续保留。
- 音频包使用 SHA-256 验证内容，保留导入器的原始来源 MD5，使转换后的 NWA/OWP 等文件继续按原始来源查重。
- 同步包复制真实音频与封面，导出和导入均需要额外磁盘空间；库外引用文件不作为受管理歌曲导出。

## 遇到问题

- 找不到同步按钮：确认启动的是更新后的开发版。旧 EXE 没有此功能。
- 预览后提示数据或同步包变化：重新选择 `manifest.json`，重新预览再确认。
- 提示文件无效或已改变：确认复制了完整文件夹，且未改名、移动包内文件或编辑清单；必要时从来源重新导出。
- 双方都修改了同一首歌：根据本次需要选择保留本地或采用同步包；这不是逐字段自动解决冲突。
